     1→# Platform Website Structure & UX Specification
     2→
     3→Scope: Information architecture · Page specifications · Interaction design · Functionality · Routing
     4→
     5→## 1. Platform structure at a glance
     6→
     7→The website should combine three complementary experiences:
     8→
     9→- Discover: Browse component categories, search the library, and explore use cases.
    10→- Explore: Interact with live components, adjust their properties, and understand their behavior.
    11→- Implement: Access installation instructions, API documentation, code examples, and integration guidance.
    12→
    13→The platform should feel like a professional software-development tool rather than a conventional marketing website or a simple gallery of UI elements.
    14→

    42→
    43→| Item          | Purpose                                                |
    44→| ------------- | ------------------------------------------------------ |
    45→| Components    | Discover and browse the library                        |
    46→| Documentation | Learn how to install and use components                |
    47→| Examples      | Explore components in realistic application interfaces |
    48→| Resources     | Find patterns, recipes, and reusable solutions         |
    49→| Search        | Search components, APIs, guides, and examples          |

   327→#### Required page regions
   328→
   329→A. Component header
   330→
   331→- Component name and concise description.
   332→- Category breadcrumb.
   333→- Component status.
   334→- Links to source code and contribution information, when available.
   335→
   336→B. Live preview
   337→
   338→- Render the actual vanilla JavaScript component.
   339→- Allow direct manipulation.
   340→- Provide a reset-to-default action.
   341→- Support preview resizing where relevant.
   342→- Display selected output values when useful.
   343→
   344→C. Interactive property inspector
   345→
   346→For the Color Wheel Picker:
   347→
   348→- Inner shape selector: triangle, square, disk, none.
   349→- Inner shape size control.
   350→- Wheel thickness and spacing controls, if exposed by the component API.
   351→- Current hue and color values.
   352→- Additional controls only when supported by the component.
   353→
   354→Changing a property must update the actual preview immediately. The inspector must not simulate configuration using independent decorative elements.
   355→
   356→D. Output and color information
   357→
   358→- Display the current color in HEX.
   359→- Offer RGB, HSV, and HSL representations.
   360→- Provide a copy action for individual values.
   361→- Keep values synchronized with direct interaction.
   362→
   363→E. Implementation tabs
   364→
   365→- Preview.
   366→- HTML markup.
   367→- JavaScript initialization and configuration.
   368→- CSS and customization.
   369→- Optional framework integration examples.
   370→
   371→The source examples must use the real public API and must not imply that Next.js or React is required to run the component.
   372→
   373→F. Documentation content
   374→
   375→- Overview and use cases.
   376→- Installation.
   377→- Basic usage.
   378→- Configuration properties.
   379→- Events and public methods.
   380→- Accessibility and keyboard behavior.
   381→- Examples and known limitations.
   382→
   383→Interaction rule: Changes made in the playground should be reflected in the preview and generated code. If a configuration is unsupported, the interface should explain why rather than displaying code that does not work.

   473→## 6. Global Interaction Specifications
   474→
   475→| Interaction           | Expected behavior                                            |
   476→| --------------------- | ------------------------------------------------------------ |
   477→| Global search         | Search component names, categories, docs, and examples       |
   478→| Sidebar navigation    | Navigate between sections and preserve the active page state |
   479→| Breadcrumbs           | Navigate to parent sections                                  |
   480→| Theme toggle          | Change the site's theme consistently                         |
   481→| Preview controls      | Update the actual component instance                         |
   482→| Code tabs             | Show the corresponding implementation example                |
   483→| Copy controls         | Copy the associated value or code snippet                    |
   484→| Reset preview         | Restore documented default settings                          |
   485→| Section anchors       | Navigate directly to documentation sections                  |
   486→| Browser navigation    | Back and forward actions restore the correct route           |
   487→| Responsive navigation | Open and close mobile navigation without losing context      |
   488→
   489→Interactive controls must have visible focus states, appropriate disabled states, clear labels, and meaningful feedback.
   490→
   491→## 7. Search and Discovery
   492→
   493→The search experience should be global rather than limited to the currently visible category.
   494→
   495→Searchable content:
   496→
   497→- Component names and aliases.
   498→- Categories.
   499→- Component descriptions.
   500→- API methods and configuration properties.
   501→- Documentation headings.
   502→- Example names and use cases.
   503→
   504→Expected behavior:
   505→
   506→1. Open search from the header or a keyboard shortcut.
   507→2. Enter a query.
   508→3. Display grouped results by content type.
   509→4. Highlight matching terms when practical.
   510→5. Navigate to the selected result.
   511→6. Preserve the previous page when the user returns from a result.
   512→
   513→Keyboard shortcuts should be documented and must not conflict with browser or assistive-technology conventions.

   532→
   533→- Experienced developer: Search directly for a method or component property, then jump to its reference.
   534→- Visual explorer: Browse examples, open a component used in an example, and inspect its configuration.
   535→- Contributor: Discover a component, review its implementation requirements, and navigate to contribution guidance.

   539→## 9. Shared Design and Content Rules
   540→
   541→- Use consistent page headers, breadcrumbs, section headings, and documentation conventions.
   542→- Prioritize readable technical content and usable interactive previews.
   543→- Keep component demonstrations visually neutral enough to distinguish the component from the website's branding.
   544→- Use consistent spacing, typography, icon sizing, borders, and interaction states.
   545→- Provide light and dark themes if supported by the component library's design goals.
   546→- Avoid unnecessary dashboards, accounts, social features, or community systems in the initial release.
   547→- Treat the component API and actual behavior as the source of truth for the playground and documentation.

   549→## 10. Recommended Delivery Phases
   550→
   551→1. Phase 1 — Platform foundation
   552→
   553→   Establish navigation, global shell, component directory, category pages, documentation structure, and routing conventions.
   554→2. Phase 2 — Component documentation engine
   555→
   556→   Establish reusable component page layouts, live preview containers, property inspectors, code tabs, and API documentation sections.
   557→3. Phase 3 — First integrated component

   559→   Integrate the Color Wheel Picker and connect its real configuration API to the playground, output display, and code examples.
   560→4. Phase 4 — Developer experience
   561→
   562→   Add global search, responsive navigation, theming documentation, keyboard support, and copy-to-clipboard behavior.
   563→5. Phase 5 — Examples and project resources
   564→
   565→   Add realistic application examples, contribution guidance, and release documentation.

   567→## 11. Acceptance Criteria
   568→
   569→The platform's initial structure is ready when:
   570→
   571→- Every primary section has a defined purpose and route.
   572→- Components are discoverable through both category browsing and global search.
   573→- Each component has a consistent documentation and playground layout.
   574→- The live preview can be controlled through its documented properties.
   575→- Code examples correspond to the actual vanilla JavaScript API.
   576→- Documentation clearly distinguishes the platform's framework from the component implementation.
   577→- Navigation, breadcrumbs, browser history, and responsive layouts work consistently.
   578→- The initial Color Wheel Picker can be discovered, tested, understood, and integrated without requiring a developer account.
