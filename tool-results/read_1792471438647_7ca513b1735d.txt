     1→     1→# Platform Website Structure & UX Specification
     2→     2→
     3→     3→Scope: Information architecture · Page specifications · Interaction design · Functionality · Routing
     4→     4→
     5→     5→## 1. Platform structure at a glance
     6→     6→
     7→     7→The website should combine three complementary experiences:
     8→     8→
     9→     9→- Discover: Browse component categories, search the library, and explore use cases.
    10→    10→- Explore: Interact with live components, adjust their properties, and understand their behavior.
    11→    11→- Implement: Access installation instructions, API documentation, code examples, and integration guidance.
    12→    12→
    13→    13→The platform should feel like a professional software-development tool rather than a conventional marketing website or a simple gallery of UI elements.
    14→    14→

   327→   327→#### Required page regions
   328→   328→
   329→   329→A. Component header
   330→   330→
   331→   331→- Component name and concise description.
   332→   332→- Category breadcrumb.
   333→   333→- Component status.
   334→   334→- Links to source code and contribution information, when available.
   335→   335→
   336→   336→B. Live preview
   337→   337→
   338→   338→- Render the actual vanilla JavaScript component.
   339→   339→- Allow direct manipulation.
   340→   340→- Provide a reset-to-default action.
   341→   341→- Support preview resizing where relevant.
   342→   342→- Display selected output values when useful.
   343→   343→
   344→   344→C. Interactive property inspector
   345→   345→
   346→   346→For the Color Wheel Picker:
   347→   347→
   348→   348→- Inner shape selector: triangle, square, disk, none.
   349→   349→- Inner shape size control.
   350→   350→- Wheel thickness and spacing controls, if exposed by the component API.
   351→   351→- Current hue and color values.
   352→   352→- Additional controls only when supported by the component.
   353→   353→
   354→   354→Changing a property must update the actual preview immediately. The inspector must not simulate configuration using independent decorative elements.
   355→   355→
   356→   356→D. Output and color information
   357→   357→
   358→   358→- Display the current color in HEX.
   359→   359→- Offer RGB, HSV, and HSL representations.
   360→   360→- Provide a copy action for individual values.
   361→   361→- Keep values synchronized with direct interaction.
   362→   362→
   363→   363→E. Implementation tabs
   364→   364→
   365→   365→- Preview.
   366→   366→- HTML markup.
   367→   367→- JavaScript initialization and configuration.
   368→   368→- CSS and customization.
   369→   369→- Optional framework integration examples.
   370→   370→
   371→   371→The source examples must use the real public API and must not imply that Next.js or React is required to run the component.
   372→   372→
   373→   373→F. Documentation content
   374→   374→
   375→   375→- Overview and use cases.
   376→   376→- Installation.
   377→   377→- Basic usage.
   378→   378→- Configuration properties.
   379→   379→- Events and public methods.
   380→   380→- Accessibility and keyboard behavior.
   381→   381→- Examples and known limitations.
   382→   382→
   383→   383→Interaction rule: Changes made in the playground should be reflected in the preview and generated code. If a configuration is unsupported, the interface should explain why rather than displaying code that does not work.

   491→   491→## 7. Search and Discovery
   492→   492→
   493→   493→The search experience should be global rather than limited to the currently visible category.
   494→   494→
   495→   495→Searchable content:
   496→   496→
   497→   497→- Component names and aliases.
   498→   498→- Categories.
   499→   499→- Component descriptions.
   500→   500→- API methods and configuration properties.
   501→   501→- Documentation headings.
   502→   502→- Example names and use cases.
   503→   503→
   504→   504→Expected behavior:
   505→   505→
   506→   506→1. Open search from the header or a keyboard shortcut.
   507→   507→2. Enter a query.
   508→   508→3. Display grouped results by content type.
   509→   509→4. Highlight matching terms when practical.
   510→   510→5. Navigate to the selected result.
   511→   511→6. Preserve the previous page when the user returns from a result.
   512→   512→
   513→   513→Keyboard shortcuts should be documented and must not conflict with browser or assistive-technology conventions.
