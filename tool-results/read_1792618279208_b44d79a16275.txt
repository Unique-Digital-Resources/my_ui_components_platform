    40→    40→- Created `src/lib/components/color-wheel/color-utils.ts` (308 lines): pure color math — `hsvToRgb` / `rgbToHsv` / `rgbToHex` / `hexToRgb` / `hsvToHsl` / `hslToHsv`, a `parseColor` that accepts hex / `rgb()` / `hsl()` / named colors / `{r,g,b}` / `{h,s,v}` / `{h,s,l}` objects, plus `formatHex`, `toColorOutput`, `clamp`, `clampHue`. No DOM, no side effects, no dependencies.
    41→    41→- Created `src/lib/components/color-wheel/color-wheel-picker.ts` (1166 lines): the `ColorWheelPicker` class.
    42→    42→  - Single `<canvas>` renderer; scoped CSS injected once per document (`#color-wheel-picker-styles`) with `--color-picker-*` custom properties for host overrides (marker borders, focus ring, background).
    43→    43→  - Geometry: `innerR = size/2`, `wheelInnerR = innerR + wheelSpacing`, `wheelOuterR = wheelInnerR + wheelThickness`, `total = wheelOuterR * 2`, `cx = cy = total/2` — wheel stays centered on the inner shape.
    44→    44→  - Hue mapping: 0° at top, clockwise; `angle = -π/2 + hue·π/180`; inverse `theta = atan2(dx, -dy)`.
    45→    45→  - Hue wheel: 360 one-degree arc segments filled with `hsl(i, 100%, 50%)`. Cached as an offscreen canvas keyed by `(total, dpr)` so it only re-renders when geometry or DPR changes.
    46→    46→  - Triangle: equilateral HSV triangle (A=top/white, B=bottom-right/pure hue, C=bottom-left/black). Per-pixel barycentric rendering with ~1px anti-aliased coverage. `V = α+β`, `S = β/V`.
    47→    47→  - Square: inscribed square (`side = innerR·√2`) with 3 stacked gradients — pure hue → white-to-transparent (S) → transparent-to-black (V). Clipped to the square.
    48→    48→  - Disk: polar mapping `r → S`, `θ → V = (1+cos θ)/2`. Smooth, seam-free; the tracked `diskTheta` field disambiguates the two θ values that map to the same V so the inner marker stays where the user dragged it.
    49→    49→  - `none` mode: only the wheel + a solid filled inner circle in the current color; inner area is non-interactive.
    50→    50→  - Inner-shape canvas cached per `(shape, total, dpr, hue)` so SV drags only redraw the cheap markers and hue drags only re-render the inner shape (not the wheel).
    51→    51→  - Markers: hue marker = white-halo + dark-ring + pure-hue dot at the wheel mid-radius; inner marker = same triple-ring with the selected color in the center. Both stay perceivable against any hue/SV.
    52→    52→  - Pointer interaction: `pointerdown` routes by radius (wheel ring vs inner circle vs gap); `setPointerCapture` for clean dragging; `pointermove` updates hue or SV continuously; `input` fires on every move, `change` on `pointerup`/`pointercancel`. Triangle drag clamps barycentric to ≥ 0 and renormalizes; square clamps to `[0,1]`; disk clamps radius.
    53→    53→  - Keyboard: `ArrowLeft/Right` adjust hue by 1° (Shift = 10°); `Ctrl/Cmd+ArrowLeft/Right` adjust saturation; `ArrowUp/Down` adjust value (Shift = 10); `Home/End` wrap hue. Each key press emits `input` + `change`.
    54→    54→  - Public API exactly matches the PRD contract: `constructor(container, options?)`, `setColor(color)`, `getColor()`, `setShape(shape)`, `setSize(size)`, `setHue(hue)`, `on/off(event, handler)`, `destroy()`. `setColor`/`setHue` accept programmatic updates and fire `input` + `change`. `setShape`/`setSize` preserve the current color (geometry-only changes).
    55→    55→  - Tiny internal EventEmitter: `Map<string, Set<ColorHandler>>`. `emit` clones the handler set to a plain array so a handler unsubscribing during dispatch doesn't skip siblings; listener errors are caught and logged so a single bad handler can't crash the picker.
    56→    56→  - `ResizeObserver` watches the canvas and refreshes the backing store + caches on DPR changes (e.g. window moved between monitors) — disconnected in `destroy()`.
    57→    57→  - `destroy()` is idempotent: removes all pointer/keyboard listeners, releases pointer capture, disconnects the ResizeObserver, clears the handler map, removes the canvas from the DOM, drops the container class, clears the canvas, and nulls both offscreen caches.
    58→    58→- Created `src/lib/components/color-wheel/index.ts` re-exporting the class, the `Shape`/`ColorPickerOptions` types, the `RGB`/`HSV`/`HSL`/`ColorOutput`/`ColorInput` types, and the color-math utilities.
    59→    59→- Ran `bun run lint` — clean (0 errors, 0 warnings) after fixing two issues: replaced the `Function` type on `on`/`off` overloads with the explicit `ColorHandler = (color: ColorOutput) => void` to satisfy `@typescript-eslint/no-unsafe-function-type`, and removed an unused `eslint-disable-next-line no-console` directive. Ran `bunx tsc --noEmit` — no type errors in the new files (only unrelated pre-existing errors in `examples/` and `skills/`).

  1306→  1306→Task ID: 30
  1307→  1307→Agent: main
  1308→  1308→Task: Fix resize displacement after rotation — compute position from new AABB
  1309→  1309→
  1310→  1310→Work Log:
  1311→  1311→- **Root cause identified**: When an item is rotated, its AABB width = `|w·cos(θ)| + |h·sin(θ)|` — this is NOT proportional to the item's width `w` alone. The previous code scaled the item's position by the AABB scale factor `sx` (from `newW / aabb.w`) and also scaled the item's width by `sx`. But since the AABB width depends on both `w` and `h` (and `θ`), scaling `w` by `sx` doesn't produce an item whose new AABB has width `newW`. The mismatch between the expected AABB and the actual AABB of the resized item causes the item to drift on each frame of the drag.
  1312→  1312→- **Fix**: Rewrote the per-item resize math in `applyResize()`:
  1313→  1313→  1. Compute the new item width/height by scaling the start values by `sx`/`sy` (same as before).
  1314→  1314→  2. Compute the **new AABB** for the item using the new width/height and the item's rotation: `newAabbW = newW·|cos(θ)| + newH·|sin(θ)|`.
  1315→  1315→  3. Compute the **start AABB** for the item similarly.
  1316→  1316→  4. Compute the item's start AABB left edge offset from the fixed selection edge: `startOffset = startItemLeft - fixedBoardX`.
  1317→  1317→  5. Scale this offset by `sx`: `newOffset = startOffset * sx`.
  1318→  1318→  6. Position the item center at: `item.x = fixedBoardX + newOffset + newAabbW / 2`.
  1319→  1319→  
  1320→  1320→  This ensures the item's AABB edge maintains its proportional position relative to the fixed selection edge, and the item center is computed from the NEW AABB (not the old position scaled). The fixed edge stays truly fixed, and the item doesn't drift.
  1321→  1321→
